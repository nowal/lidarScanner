# Assistant-only scan update replies

This feature is additive to PR #10 (`c66c48d`); it does not use a hidden homeowner turn. The detailed server/mobile investigation is in the mobile repository’s `docs/scan-update-ai-audit.md`.

## API

`POST /api/v1/ai/home-chat/scan-update`, with the usual service bearer and verified `X-Homeowner-Token` (anonymous guest or upgraded account):

```json
{"threadId":"existing-thread","homeId":"<scan UUID>","revision":"<current upload UUID>"}
```

Response:

```json
{
  "threadId": "existing-thread",
  "homeId": "<scan UUID>",
  "revision": "<current upload UUID>",
  "status": "ready",
  "eventId": "<stable event UUID>",
  "message": {"id":"<same UUID>","role":"assistant","content":"…","createdAt":"…","attachments":[]},
  "delivered": false
}
```

`pending` means another worker is generating or an attempt is in backoff; `none` means unchanged/first context (no message). The client must match home/thread/revision, defer while its ordinary turn is in flight, and atomically save the message and event ID with its transcript. **Only then** send the same request with `deliveredEventId`. A generated response is not proof of delivery. Saved responses remain recoverable even when `delivered` is true; clients deduplicate by event ID.

Errors: 401 unverified session, 403 foreign owner/thread-home association, 409 stale revision or context/thread not ready (structured `code`/`retryable`), 429 turn contention/rate limit, 503 unavailable persistence/provider. Never synthesize a user message as fallback.

## State and grounding

Ingestion hashes canonical source geometry, frame metadata and photo bytes, excluding models, names and generated descriptions. The hash persists in the room/index. Ready context, not model completion, is the trigger. Saved `room-N` identities distinguish changed areas; aligned footprint overlap associates a newly appended capture block with an existing area when unambiguous. Unknown areas stay uncertain. Explicit homeowner names win. Legacy indices compare geometry/photo identities until source fingerprints exist.

The event provider only selects IDs of observations from the changed rooms’ ingested context; server-rendered copy cannot advance the flow or ask a question. There are no writes to flow state, quote data, normal chat logs or provider continuation. The original opener only gains an `opening_scan_revision` baseline marker.

A durable cursor tracks the last delivered context. A unique `(thread, home, capture fingerprint)` receipt tracks a pending/ready/skipped event, lease token, generated message, and separate generation/delivery times. SQL validates ownership, thread/home, ready context and current upload revision on each transition, under the same home row lock used by uploads. A rebuild sharing the capture fingerprint returns the same event. The generation timeout is 70 seconds; lease expiry is 120 seconds; failure backoff grows from 10 seconds to 5 minutes. Save retries reuse the generated message.

The existing per-process ordinary-turn guard is reused. Event leases work across workers; events cannot overwrite newer flow state because they never write it. Ordinary turns retain their existing single-process concurrency limitations. A worker dying after a provider response but before durable save can require one repeated provider call after lease recovery; persisted replies are never regenerated by normal delivery retries.

## Migration and rollout

1. Apply `backend/supabase/migrations/20261013192507_scan_update_replies.sql` after the existing staged-upload migrations.
2. Deploy this backend.
3. Ship the mobile delivery changes.

No new secrets/settings: existing Supabase service-role persistence, guest/account authentication and AI provider settings apply. The new tables have RLS, no client-role grants, service-role-only RPC access and thread/home deletion cascades. Missing migration/storage fails closed. The migration was applied to TakeShapeApp (`pxnbfdsyuzweevkvremi`) on October 13, 2026 and recorded as `20261013192507`. Its transition tests passed against the deployed function in a rolled-back transaction; no synthetic rows remained.

## Tests

- `PYTHONPATH=backend <python> -m pytest backend/ -q` (hermetic existing suite plus `test_scan_updates.py`).
- On an isolated database with a synthetic homeowner, run `backend/tests/sql/scan_upload_transitions.sql` and `backend/tests/sql/scan_update_replies.sql`. Each rolls back its synthetic rows. The latter checks leases, readiness/failure recovery, ownership, generation vs delivery, model-only rebuilds, stale responses, unchanged flow fields, RLS/grants and cascades.
- Mobile tests cover transcript/event atomicity, ACK loss, local-write failures, duplicate suppression, stale response checks and deferral during ordinary turns. Build and simulator checks do not establish live-device/backend operation.
